# 篮球球星卡公网联机版

这是一个 2-3 人实时联机网页桌游。一个 Node.js 服务同时提供前端网页、静态资源、健康检查接口和 Socket.IO WebSocket 服务。

部署到 Render 这类支持 WebSocket 的公开 Node.js Web Service 后，玩家可以在不同城市、不同运营商、手机流量或不同 Wi-Fi 下，通过同一个公开 HTTPS 网址和 6 位房间码进入同一个房间。

## 技术栈

- Node.js
- Express
- Socket.IO
- 原生 HTML、CSS、JavaScript
- Vite 仅用于把前端资源构建到 `dist/`
- 第一版房间状态保存在服务端内存中

## 已实现

- 创建房间，服务器生成 6 位房间码。
- 输入房间码加入，人数限制 2-3 人。
- 重复名字自动改名，第四名玩家会被拒绝。
- 玩家准备，只有房主可以开始游戏。
- 游戏开始后禁止陌生玩家加入。
- 房主断开后自动转交给仍在线玩家。
- 游戏结束后可在原房间重新开始，并清理旧牌库、手牌、弃牌和行动状态。
- 刷新或短暂断线后使用 `roomCode` + `playerToken` 恢复原座位。
- 每个操作携带 `actionId`，服务端防止重复扣钱、重复抽牌、重复签约等。
- 每次状态更新包含递增的 `stateVersion`，客户端会忽略旧状态。
- 服务器为每位玩家分别生成可见状态，不广播完整房间对象。
- 客户端使用 `io()` 同源连接，不写死 localhost、127.0.0.1、局域网 IP 或个人电脑 IP。
- `GET /health` 返回 `{ "ok": true }`。

## 服务端权威状态

客户端只提交操作请求，例如选择哪个手牌 ID、目标玩家 ID、薪资输入和 `actionId`。以下内容均由服务端决定：

- 洗牌和牌库顺序
- 初始手牌
- 随机弃牌和弃牌分数
- 选秀顺序
- 随机交易结果
- 钞票增减
- 球员归属
- 当前回合
- 操作是否合法
- 游戏是否结束
- 最终得分

其他玩家不会收到你的真实手牌；未授权的隐藏选秀牌也不会发送到他们的浏览器。

## 本地运行

推荐 Node.js 20+。

```bash
npm install
npm start
```

`npm install` 会自动执行前端构建。启动后打开服务输出对应的地址。本地开发也可以使用：

```bash
npm run dev
```

## 测试

```bash
npm test
```

自动测试覆盖：

1. 可以创建房间。
2. 可以从第二个客户端加入。
3. 第三个客户端可以从不同会话加入。
4. 第四名玩家不能加入。
5. 非房主不能开始游戏。
6. 玩家未准备时不能开始。
7. 客户端不能获得对手真实手牌。
8. 非当前玩家不能操作。
9. 客户端不能伪造球员分数。
10. 客户端不能伪造钞票数量。
11. 同一 `actionId` 不会执行两次。
12. 刷新后能恢复座位。
13. 无效令牌不能恢复其他人的座位。
14. 房间之间的数据不能互相泄露。
15. 游戏结束后停止接受游戏操作。
16. 重新开始会清理旧牌库、手牌、弃牌和行动状态。

## Render 部署步骤

1. 将项目上传到 GitHub。
2. 在 Render 创建 Web Service。
3. 连接该 GitHub 仓库。
4. Build Command 设置为 `npm install`。
5. Start Command 设置为 `npm start`。
6. 部署后获得 Render 提供的公开 HTTPS 网址。
7. 用两个不同网络的设备测试：一台使用手机流量，一台使用另一个地点或另一个 Wi-Fi，打开同一个公开 HTTPS 网址，通过同一个房间码加入。

本项目也提供 `render.yaml`，Render Blueprint 可以直接读取：

- `buildCommand: npm install`
- `startCommand: npm start`
- `healthCheckPath: /health`

## 公网验收

部署成功后，按以下流程验收：

1. 玩家 A 打开公开 HTTPS 游戏网址。
2. 玩家 A 点击“创建房间”，复制 6 位房间码。
3. 玩家 B 使用手机流量打开同一网址并输入房间码加入。
4. 玩家 C 使用另一个地点的 Wi-Fi 打开同一网址并输入房间码加入。
5. 2-3 人准备后，房主开始游戏。
6. 每名玩家只能看到自己的手牌和自己有权查看的私人选秀牌。
7. 刷新页面后，原浏览器应自动恢复原座位。
8. 两台或三台设备能实时看到玩家加入、准备、回合和公开状态变化。

## 重要限制

- 房间状态保存在单个 Node 进程内，服务重启或 Render 免费实例休眠重启会清空房间。
- 身份令牌保存在浏览器 `localStorage`，更换浏览器或清空缓存后无法恢复原座位。
- 当前版本没有账号、观战、聊天、数据库持久化或跨实例扩展。

## 规则依据

规则来源：`assets/rule/game-rules.md`。当前实现保留项目内现有规则：

- 2-3 名玩家。
- 每人初始 3 张手牌。
- 每人初始 15 个钞票。
- 所有玩家强制参加选秀。
- 左边玩家抽取目标玩家的一张隐藏手牌并弃掉。
- 根据被弃牌分数确定选秀顺序。
- 选秀牌数量为玩家人数加 1。
- 每名玩家小回合可签约、交易、挖角。
- 每项操作每个小回合最多一次。
- 牌库抽完后完成当前大回合。
- 签约区球员总分最高者获胜。
